# THE BOSS fullstack v1.1.1 — release notes

Prepared 2026-09-21 as a small RPC-provider compatibility patch on top of v1.1.

## What changed

- Changed the default `SCAN_CHUNK_BLOCKS` from 800 to 10.
- Removed the hard-coded 800-block range from the Treasury event scanner; it now uses `SCAN_CHUNK_BLOCKS`.
- Added `RPC_LOG_PAGE_DELAY_MS` (default 75 ms) and use it between paged log requests in Treasury scanning, trade scanning, and launch discovery.
- Updated `.env.example`, README and validation notes.
- Bumped package version to `1.1.1`.

## Why

The user's Alchemy Free-tier Robinhood Chain RPC returned an explicit provider error saying `eth_getLogs` requests may cover at most 10 blocks. v1.1 still used an 800-block Treasury event page, so the request was rejected even though normal `eth_call` traffic was healthy.

This patch keeps the current Alchemy endpoint and works within that provider limit. It does not change BOSS economics, contract logic, reporter rules, wallet roles, launch sequence, or any safety gate.

## Carry-over `.env` values

Keep the existing private Alchemy RPC URL. Do not copy secrets into the ZIP. Ensure these values are present:

```dotenv
RPC_POLL_MS=10000
SCAN_CHUNK_BLOCKS=10
RPC_LOG_PAGE_DELAY_MS=75
OPERATIONS_ENABLED=false
TRADER_ADAPTER_VERIFIED=false
V4_REPORTING_ENABLED=false
```

Then run `npm run check`, `npm run build`, `npm run smoke`, and `npm run dev`.
